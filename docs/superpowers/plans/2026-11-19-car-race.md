# Car Race Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chat-Autorennen als Mini-Overlay: `!race`-Anmeldung (3–10), Zufallsautos aus dem Katalog mit eigenen Werten, gerechnetes Rennen auf erzeugter Strecke, Siegerehrung, Punkte monatlich + ewig.

**Architecture:** Server (`fx/race.py`) hält Lobby und Uhr je Tenant im Speicher und vergibt Seed + Autos; Ergebnisse dauerhaft in `fx/race_db.py`. Overlay `effects/car-race.html` pollt den Zustand, rechnet das Rennen deterministisch aus dem Seed (`js/car-race-sim.js`, ohne DOM, in Node testbar) und zeigt es mit three.js (`js/car-race.js`); es meldet das Ergebnis einmal je Rennen-ID.

**Tech Stack:** Python/Flask (`fx/`), pytest, sqlite in Tests / Postgres auf Prod über `core.db_compat`, vanilla JS + three.js r128, Node für JS-Prüfungen.

**Spec:** `docs/superpowers/specs/2026-11-19-car-race-design.md`

## Global Constraints

- Keine Inline-Styles (kein `style="…"`, kein JS-`.style`/`style.setProperty`); farbige Einzelwerte (Chatfarbe, Lackfarbe) werden in Canvas gezeichnet, nicht per CSS gesetzt.
- Sichtbare Texte englisch; Kommentare, Commits deutsch mit Umlauten, Conventional Commits, kein Co-Authored-By, direkt auf master.
- Kein Build-Tool, kein npm; Vendor-Dateien aus `js/vendor/` (three r128).
- Je Tenant getrennt: Routen `/s/<token>/api/fx/car-race…`, Tabellen mit `tenant_id`.
- SQL mit `?`-Platzhaltern (nie `%s`).
- Teilnehmer 3–10, Countdown 60 s, Rennen max. 90 s, Nachlauf nach dem Sieger X s (Standard 15), Podium ~10 s, Lobby verfällt nach 5 min, Pause 2 min, Ergebnis-Frist 2 min nach Start.
- Punkte = geschlagene Fahrer (inkl. DNF) + 1 Siegbonus; DNF = 0 Punkte, `place` NULL.
- Overlay 16:9, Standard 640×360; Free-Standard-Modelle nie ins Repo.
- Nur betroffene Testdateien laufen lassen, nie die ganze Suite. README mit jedem Feature-Task aktualisieren.
- Deploy: `ssh root@31.70.95.217`, `cd /opt/obs-stream-kit && git pull --ff-only`, Python-Änderung → `systemctl restart obs-stream-kit obs-overlays`; neue Tabelle per `sudo -u postgres psql` mit `obs.`-Schema-Präfix.

## Review Focus

1. Doppelte Ergebnismeldung (zwei Overlays/Neuladen) → zählt genau einmal (Task 1 Test `test_record_is_idempotent`).
2. Overlay wird mitten im Rennen eingeblendet → springt per Vorspulen an die richtige Stelle, gleiches Ergebnis wie von Anfang an (Task 3 `fastForward`-Prüfung).
3. Schwerfahrzeug gegen starkes Feld → gewinnt manchmal, Favorit nicht immer (Task 3 Bilanz-Prüfung 2 % / 45 %).
4. `!race` in falscher Phase (Rennen läuft, Pause, Feld voll, doppelt) → freundliche Absage, keine Zustandsänderung (Task 2 Tests).
5. Katalog ohne passende Autos / Modell lädt nicht → Rennen läuft trotzdem (Fallback-Auto aus Katalog bzw. Ersatz-Kiste), kein Hänger (Task 6 Fallback).
